# STE100 documentation standard

This project writes its documentation in ASD-STE100 Simplified Technical English.
The rules below apply to the English prose. They do not apply to code blocks, command lines, or tables.

## Rules

1. Write short sentences. Use 20 words or fewer for an instruction. Use 25 words or fewer for a description.
2. Use the active voice.
3. Use the imperative for instructions.
4. Use the simple present.
5. Use one word for one meaning. Use the glossary.
6. Do not use a gerund.
7. Do not use a contraction.
8. Do not use a semicolon.
9. Do not use `should`, `may`, `might`, `could`, or `would`. Use `must` or `can`.
10. Do not use `e.g.`, `i.e.`, or `etc.`.
11. Do not use an idiom or a metaphor.
12. Do not use a noun cluster with more than three nouns.
13. Put one instruction in one sentence.
14. Put the condition before the action.
15. Use "must" for a requirement. Use "can" for a possibility. Use "do not" for a prohibition.

## Scope

The lint checks these files:

- `README.md`
- `AGENTS.md`
- `CLAUDE.md`
- `skills/produce-video/SKILL.md`
- `skills/produce-video/references/prompt-framework.md`
- `docs/*.md`

The lint does not check code blocks, tables, command lines, or the CHANGELOG. The CHANGELOG is a historical record.

## Glossary

| Term | Meaning |
|---|---|
| the toolkit | the knowledge-video-studio project |
| episode | one video in a series |
| series | a group of episodes |
| brief | the approved creative plan |
| fact card | the source and number record |
| fact check | the claim-level review record |
| frame | one picture at one time |
| render | draw and capture a frame, then encode the frames |
| capture | take a PNG from the browser |
| seek | move a timeline to a time |
| agent | the AI worker |
| reviewer | the person who signs a check |
| must | a requirement |
| can | a possibility |

The JSON schema IDs keep the `storyweaver.` prefix. This prefix is a compatibility namespace.
Do not change the prefix without a migration.

## Run the lint

```bash
node studio/cli.mjs docs-lint
```

The command exits with code 1 when it finds a violation. A test also runs the lint.
